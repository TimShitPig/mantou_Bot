<summary>查看群管功能</summary>

用户发送的消息中包含连续 9 到 12 位数字时，插件会尝试撤回该消息。群名片、JSON 卡片、QQ 官方显示为“暂不能查看该消息内容”的空间相册分享、合并转发和 QQ 闪传也会走同一个撤回模块。QQ 群主和管理员发送的消息不会被自动撤回；插件会优先用 OneBot `get_group_member_info` 查询真实 QQ 群成员角色，只有查不到时才使用事件里的 `role` 兜底。普通成员当前消息撤回成功后，会通过 `get_group_msg_history` 拉取最近 100 条群历史，筛选该用户最近消息并逐条调用 `delete_msg` 撤回，默认最多撤回 8 条；随后同时提及配置管理员和发送者，并使用发送者昵称生成撤回通知，按群 5 分钟限频。QQ 官方群需要在配置中填写管理员 OpenID；通知正文会清除数字、链接和卡片元数据。

本模块暂不提供踢人功能；发送 `开启禁言` / `关闭禁言`、`开启全员禁言` / `关闭全员禁言`，或 `禁全体` / `禁言全体` / `全体禁` / `全体禁言`、`解全体` / `解禁全体` / `全体解禁` / `全体解`，会开关当前群全员禁言；发送 `开启全部禁言` / `关闭全部禁言` 会先获取机器人所在群再逐群开关。发送 `禁言 @成员` 或 `禁 @成员` 默认禁言 7 天；`禁 @成员 1` 表示 1 天，带 `秒`、`分`、`时`、`天` 时按对应单位计算；成功后会 @被禁言成员并提示“你已经被禁言，请联系群主说明情况”；`解除禁言 @成员` 或 `解 @成员` 立即解除。OneBot 使用 `set_group_ban`，QQ 官方群使用官方成员禁言接口；QQ 官方公开文档目前提供全员禁言状态查询，但没有公开全员禁言写入接口，因此全员禁言仍按适配器提供的 `set_group_whole_ban` 能力执行。

将插件目录放入 AstrBot 的 `data/plugins` 目录，然后在 AstrBot WebUI 的插件管理中重载插件。

## 插件配置

| 配置项 | 说明 |
| --- | --- |
| `group_file_cleanup_admin_qq` | 群文件清理管理员 QQ 白名单，可使用帮助、状态、群文件清理、全部群文件清理、群文件状态、全量消息、小说网盘切换、保存三种网盘与 QQ阅读 Cookie、小说开关和禁言指令 |
| `uc_pan_settings` | UC 网盘配置分类，包含 `uc_pan_cookie` 和 `uc_pan_upload_dir`；发送 `换UC` 后作为小说主分享网盘 |
| `quark_pan_settings` | 夸克网盘配置分类，包含 `quark_pan_cookie` 和 `quark_pan_upload_dir`；发送 `换夸克` 后作为小说主分享网盘 |
| `baidu_pan_settings` | 百度网盘配置分类，包含 `baidu_pan_cookie`、`baidu_pan_upload_dir` 和 `baidu_pan_upload_status`；发送 `换百度` 后作为主分享网盘，选择其他主网盘时仍可按状态后台备份 |
| `database_settings` | 数据库配置分类，包含 `database_host`、`database_port`、`database_user`、`database_password`；数据库名默认与用户名相同 |

小说下载功能全部免费可用，不保留用户激活、卡密、收费、付费或每日免费额度。运行状态仅使用 MySQL 的 `mantou_runtime_state` 表保存群文件 Cookie、三种网盘 Cookie、QQ阅读登录态、待清理群列表、小说功能开关和当前主网盘；数据库配置在插件配置最下面的 `database_settings` 分类内，数据库名默认与用户名相同。未配置数据库时不会尝试连接 MySQL，小说功能默认全部开启，主网盘默认 UC，相关运行状态无法持久化。群文件清理管理员白名单内的 QQ 可直接粘贴 UC、夸克、百度或 QQ阅读 Cookie，无需命令前缀；三种网盘登录态保存在 `novel_pan_auth` 命名空间，QQ阅读只保存 `ywguid/ywkey`。新 Cookie 覆盖旧值，数据库登录态优先于插件配置。动态密钥池仍只保存在当前进程内，不写入本地 `keypool.cache`。

群文件清理管理员白名单内的 QQ 可发送 `状态` 查看系统位数、CPU占用、物理内存、磁盘空间、系统进程、操作系统、框架版本、数据库状态、运行时间和当前时间。每次输入 `状态` 时只执行一次数据库连通性检查，仅显示 `正常`、`未配置` 或 `异常`，不显示 Cookie、账号、IP、密钥、数据库地址、功能开关或网盘信息。

群文件清理管理员白名单内的 QQ 可发送 `帮助` 查看 `主动触发` / `被动触发` 大类，随后在 120 秒内发送数字进入小类，再发送数字查看触发指令列表，再发送数字查看详情；发送 `0` 返回上一层。也可直接发送 `帮助 1` 查看指定大类。QQ 官方 Markdown Keyboard 的帮助菜单、返回和详情快捷命令按钮均使用原生 `action.type=1` 回调：点击后不会向聊天发送指令，互动桥会投递到后端完成菜单切换或执行快捷命令；群聊仍走 `/v2/groups/{group_openid}/messages` 群消息接口。普通成员无法触发帮助功能。

群文件清理管理员白名单内的 QQ 可发送 `开启番茄` / `关闭番茄`、`开启七猫` / `关闭七猫`、`开启书旗` / `关闭书旗`、`开启QQ阅读` / `关闭QQ阅读`、`开启得间` / `关闭得间`、`开启点众` / `关闭点众` 和 `开启知乎` / `关闭知乎` 开关对应小说下载功能，状态写入 MySQL 的 `mantou_runtime_state` 表，重载后继续生效。关闭后用户发送对应小说链接会直接回复该功能已关闭，不进入下载流程。
群文件清理管理员白名单内的 QQ 可发送 `开启番茄` / `关闭番茄`、`开启七猫` / `关闭七猫`、`开启书旗` / `关闭书旗`、`开启QQ阅读` / `关闭QQ阅读`、`开启得间` / `关闭得间`、`开启点众` / `关闭点众`、`开启知乎` / `关闭知乎` 和 `开启塔读` / `关闭塔读` 开关对应小说下载功能，状态写入 MySQL 的 `mantou_runtime_state` 表，重载后继续生效。关闭后用户发送对应小说链接会直接回复该功能已关闭，不进入下载流程。

知乎小说识别 `story.zhihu.com/manuscript/paid_column/专栏ID/章节ID` 分享链接及卡片。`https://api.zhihu.com/km-indep-home/catalog/{专栏ID}` 分页返回真实目录总数、章节 ID、标题和目录字数；`https://api.zhihu.com/km-indep-home/manuscript/{专栏ID}/{章节ID}/header` 是单章详情接口，补充章节标题、专栏标题、作者、进度和前后章节指针，不直接返回正文。插件先读取完整目录，再复用异步 HTTP 会话并发请求正文提取服务（`q=专栏ID&a=章节ID`）；单章失败只重试该章，服务异常时再使用仓库内置恢复客户端。正文按目录顺序合成，缺少任意目录章节时不生成部分 TXT。

群文件清理管理员白名单内的 QQ 可发送 `网盘` / `网盘状态` / `当前网盘` 查看 UC、夸克和百度网盘配置状态；发送 `换UC`、`换夸克` 或 `换百度` 切换所有小说下载共用的主分享网盘。选择结果写入 MySQL `mantou_runtime_state`（namespace=`novel_share_pan`，state_key=`active`），重载后继续生效；只调用当前选择的网盘，不自动回退其他网盘。管理员可在私聊发送 `夸克登录`，使用夸克网盘 App 扫描 5 分钟有效二维码，成功后自动把网页 Cookie 保存到 MySQL；重复发送会取消上一轮等待。管理员也可直接粘贴普通 Cookie、`Cookie:` 请求头、curl、Cookie Editor JSON 或 Netscape cookies.txt；插件按字段自动识别平台，识别不明确时可加 `UC Cookie:`、`夸克 Cookie:` 或 `百度 Cookie:` 前缀。

UC Cookie 可继续填写到 `uc_pan_cookie`，也可由管理员直接粘贴包含 `UDRIVE_TRANSFER_SESS` 的完整 Cookie；聊天保存值写入 `novel_pan_auth/uc` 并优先于配置。上传目录读取 `uc_pan_upload_dir`，默认 `/小说机器人`。上传前会分页扫描并删除目标目录下与原小说文件名完全相同的远端普通文件，不删除同名文件夹；如果创建上传目录时返回同名冲突，会重新查找已有目录继续上传；如果 UC 上传仍返回同名冲突，插件会重新扫描并删除同名旧文件，再继续使用原小说文件名重试，不再改用备用远端文件名；如果上传完成接口返回 `23008` / `file is doloading`，插件会复用预上传阶段返回的文件 ID 继续创建分享，创建分享时文件仍在处理中也会等待重试。

夸克 Cookie 可继续填写到 `quark_pan_cookie`，也可由管理员私聊发送 `夸克登录` 扫码自动获取，或直接粘贴包含 `b-user-id` / `__uid` / `__kps` 之一和 `__puus` 的完整 Cookie；聊天保存值写入 `novel_pan_auth/quark` 并优先于配置。每次发送 `夸克登录` / `登录夸克` / `刷新夸克Cookie` 都会先彻底取消上一轮等待，再用唯一防缓存请求获取全新二维码。扫码流程跟随当前网页二维码参数，非成功轮询状态继续等待，登录态换取固定携带 `fr=pc` 与 `platform=pc`。夸克请求完全按当前网页端 `drive-pc.quark.cn` 参数执行，短时 `ctoken` 不再加入请求参数；上传目录读取 `quark_pan_upload_dir`，默认 `/小说机器人`。插件逐级创建目录、删除同名旧文件并等待删除任务完成，再按网页端预上传、哈希校验、OSS 单分片和完成上传签名创建文件，最后通过分享接口取得短链接；请求期间刷新 `__puus` 时会受控回写最新值。

百度 Cookie 可继续填写到 `baidu_pan_cookie`，也可由管理员直接粘贴包含 `BDUSS` 和 `STOKEN` 的完整 Cookie；聊天保存值写入 `novel_pan_auth/baidu` 并优先于配置。上传完成后创建带提取码的永久分享链接，提取码写入链接查询参数供按钮直接打开。选择 UC 或夸克为主网盘时，百度仍按 `baidu_pan_upload_status` 做后台备份；完结同名文件已存在时跳过，连载删除同名普通文件后重传。百度作为当前主分享网盘时跳过重复后台备份，且不受后台状态筛选限制。

任一主网盘上传成功后，QQ 官方机器人都在同一条消息中发送“宝宝你的 / 书名 / 作者 / 已经下载完成”、备用“点击此文字打开”Markdown 链接和“点击打开”链接按钮；当前主网盘未配置或上传失败时仅回复 `文件发送失败，请稍后再试`，不会改用其他网盘或发送原小说 txt。

群文件清理统一走 QQ 群文件网页接口 `pan.qun.qq.com/cgi-bin/group_file/get_file_list` 和 `delete_file`，不再使用 OneBot 适配器扩展接口，也不连接 NapCat 或 NapCat WebUI。管理员需先发送 `登录群文件` 获取登录链接，在浏览器登录后复制 Cookie，发送 `群文件登录cookie <cookie>` 保存；Cookie 支持普通 Cookie 头、`Cookie:` 头、curl `-H "Cookie: ..."`、Cookie Editor JSON 和 Netscape cookies.txt；Cookie 存 MySQL `mantou_runtime_state`（namespace=`web_group_file_cookie`，state_key=管理员QQ），按管理员 QQ 隔离，31 天有效，重载后继续生效。保存后自动开启后台保活，每 10 分钟用 `skey` 调用 qun.qq.com 账号级接口；插件启动或重载时不读取数据库启动保活。只有 `p_skey` 时可保存用于群文件接口，但不会走保活回退。管理员可发送 `群文件状态` / `群文件cookie状态` 查看 `群cookie：生效/失效`；`状态` 命令同样只显示 `群cookie：生效/失效`，不显示 Cookie 原文、上次保活和失败次数。发送 `清理群文件` / `群文件清理` 时，插件列出「添加群聊」里的目标群列表，同一会话同一发送者 120 秒内发送编号清理对应群，发送 `0` 取消；列表为空时会提示先发送 `添加群聊 群号` 添加目标群。发送 `清理全部群文件` 会先发送 `正在清理群文件（全部）`，再读取「添加群聊」添加的目标群列表，复用同一个 aiohttp session 逐群走网页接口清理，并汇总成功/失败的群数与文件数。群聊管理指令 `添加群聊 群号 [群号...]`、`删除群聊 群号 [群号...]`、`查看群聊` 仅群文件清理管理员白名单 QQ 可用，群号列表写入 MySQL `mantou_runtime_state`（namespace=`cleanup_groups`），重载后继续生效。网页接口从 Cookie 提取 `skey` 或 `p_skey` 后用 hash 算法计算 `bkn` 鉴权，文件列表每页 50 个并发拉取，删除每批 20 个并发提交，失败自动重试 3 次；当前实现只删根目录文件，不递归子文件夹；遇到 `ec != 0` 或 HTTP 非 200 时按接口错误提示重新登录。

七猫小说支持长篇链接和短篇分享链接，正文优先使用 App 批量接口下载（默认每批 500 章、最多 4 个批次并发），短篇会走短篇详情/目录和 `reader_agent=1` 正文接口。书旗小说支持 `shuqi.com/book/数字.html`、`t.shuqi.com/catalog/数字/`、`t.shuqi.com/cover/数字`、`t.shuqi.com/shortNovel/reader/数字` 和 `d.shuqi.com/短码`；书旗搜索、联想、链接识别和下载都保留在 `书旗小说.py`，下载部分以 `download_shuqi.php` 的固定 UID、盐值、M9 加密和整本 SQB/SQC 解密为核心，目录和整本下载地址并行请求，按目录章节数修正 `try_N` 后只下载一次压缩包并按目录顺序合成；缺少任意目录或正文时停止，不生成部分 TXT。下载完成后会临时写入 `功能文件/下载缓存/` 供当前主网盘分享和百度后台备份；QQ 不直接接收 txt 文件。插件每次启动或重载都会删除该目录遗留的小说 txt。发送文件名格式为 `[完结]书名：xxx 作者：xxx.txt` 或 `[连载]书名：xxx 作者：xxx.txt`，txt 文件顶部会写入免责声明。

点众小说只使用 App 详情、目录、单章正文和广告解锁接口。目录按窗口最多 500 路并发获取；正文按章节数动态创建独立 App 会话，首轮从 16 路开始、成功率稳定时最高提升至 60 路，每路复用自己的 HTTP Session 并串行解锁，避免共享身份导致正文解锁互相覆盖。遇到没有广告解锁入口的会员章节会直接标记为会员锁定，不重复请求；首轮后仅其他失败章节使用新会话低并发重试，缺少任意章节时停止合成。

塔读小说使用单文件实现：详情、批量目录和缺失章节地址补全均走 App 接口，目录和正文下载复用 aiohttp 会话，正文动态并发最高 400；TDZ 容器解密、AES/DES 算法和 UTF-16LE 正文解析直接内嵌在 `塔读小说.py`，不拆分独立加密模块。目录或正文缺少任意章节时停止合成。

塔读游客会话启动时自动注册；服务端返回有效期后，在到期前按 `earlyTime` 自动调用 `/user/api/token/get` 续期，续期失败再重新注册游客会话。登录态只保存在当前进程内，不写入插件配置或本地会话文件。

番茄小说识别 `fanqienovel.com`、`changdunovel.com`、`fqnovel.com` 和 `novelfm.com` 链接，支持 `changdunovel.com/t/短码` 分享短链和 JSON 卡片中的链接。默认走小说功能内置的番茄畅听下载逻辑：先获取书籍详情和公开目录，再使用 App 正文批量接口并发拉取小说正文，只生成 TXT，不接入音频、媒体下载、探测或命令行调试功能。下载前会先回复书名、作者、状态、章节、字数和 `正在下载中请稍等.....`；只显示接口提供的原始精确总字数，畅听副本缺少该字段时必须经书名、作者和章节数严格核验同书规范记录后补查，无法核验则显示“未知”。外部提示不显示简介，txt 文件头部保留简介，文件名格式与七猫一致。

番茄小说写入 `功能文件/下载缓存/` 后仅用于当前主网盘分享和百度后台备份；不再通过 AstrBot `File` 组件或 OneBot 文件接口发送 txt。主网盘上传成功后发送下载完成提示与“点击打开”按钮，源缓存由后台任务结束后清理；当前主网盘未配置或上传失败时只回复固定的文件发送失败提示。

QQ 官方机器人 `qq_official` 发送文件应优先走 AstrBot `File` 组件，它会封装官方富媒体接口并发送 `media` 消息；如果 QQ 官方群聊返回 `call inner proxy error`，这是平台富媒体上传限制或临时错误。OneBot 的 `upload_group_file`/`upload_private_file` 只适用于 OneBot 适配器回退。

群文件清理管理员白名单内的 QQ 在目标群发送 `全量消息` 或 `全量消息状态`，插件会调用 QQ 官方 `GET /v2/groups/{group_openid}/bot_state` 查询当前机器人的 `recv_msg_setting` 和 `allow_proactive_msg`：仅 `recv_msg_setting=all` 代表已开启“获取群内全部消息”。该官方接口目前标注为内邀开放；接口不可用时不会伪造状态。官方没有提供写入该开关的 REST 接口，群管理员需在机器人资料页中操作群消息接收设置。QQ 官方 Markdown 回复使用 `<@member_openid>` 提及操作人，不使用 QQ 号。
